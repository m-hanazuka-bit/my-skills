# 販促物 → Illustrator 編集用データ

デザイン案（画像生成 AI などで作った完成イメージ）を、**文字はテキスト・装飾はベクトル・写真は埋め込み画像** に分けて組み直し、Illustrator で開ける編集用 SVG にする。
付属の `AI保存.jsx` を Illustrator で実行すると、実寸・レイヤー分け・HG フォントの再設定・はみ出し文字の長体・CMYK 変換まで済ませた `.ai` が保存される。

```
デザイン案画像 ┐
依頼書.xlsx    ├→ ① 読む → ② サイズ確認 → ③ 素材の準備 → ④ layout.json を書く
商品画像       ┘                                            ↓
                   ⑦ ZIP で渡す ← ⑥ 見比べて直す ← ⑤ build_pop.py → preview.mjs
```

**このスキルで約束できる品質**：配置・配色・文字構成はデザイン案に近い「7〜8 割の編集用データ」。書体・筆文字・立体文字・写真の中身は完全一致しない。最後の仕上げはデザイナーが行う前提で、その旨を必ず伝える。

スクリプトは `<skill>/scripts/`（`<skill>` はこの SKILL.md のあるフォルダー）。作業フォルダーは任意（例 `work/`）。

## 0. 準備（初回だけ）
- Python 3（標準ライブラリだけで動く。Pillow があれば画像の縮小・webp 変換に使う）
- Node 18+ と Playwright の Chromium（プレビュー用。`npm i -g playwright` 済みの環境ならそのまま）
- プレビュー用フォント（HG フォントの代わりに似た無料書体で描く）：
  ```bash
  python3 <skill>/scripts/fetch_fonts.py --out ~/.cache/hansoku-ai-data/fonts \
    "Mochiy Pop P One" "Noto Sans JP:wght@500;700;900" "Zen Maru Gothic:wght@700" "Shippori Mincho B1:wght@800" "Yuji Syuku"
  ```

## 1. 受け取ったものを読む
- **依頼書（xlsx）**：`python3 <skill>/scripts/read_request.py 依頼書.xlsx --images work/req_images`
  入力済みセルが「セル番地: 値」で全部出る。✓・レ・☑ の位置から用途（POP/告知物/SNS/HP）、希望サイズ、写真かイラストかを読み取る。
  商品名・制作意図・納期・展開場所＆期間・その他を拾う。**制作意図が紙面の主役**。
  貼り付け画像（商品写真のことが多い）は `work/req_images/` に取り出される。
  非表示シート（hidden）は古い版のことが多い。表示中のシートを優先する。
- **デザイン案画像**：見て、要素を上から順に書き出す（冠リボン・大見出し・煽り文句・吹き出し・説明文・バッジ・下帯・写真の位置）。
  配色は 5〜7 色に絞って HEX で控える。
- **商品画像**：正式な写真。紙面の商品写真は、デザイン案から切り抜いたものより**こちらを優先**する。

足りない情報（商品名の正式表記、価格の有無など）があれば、次のサイズ確認と一緒に 1 回で聞く。

## 2. サイズを聞く
依頼書やメッセージにサイズがあっても、必ず確認する。AskUserQuestion が使える環境ならそれで聞く（無ければ文章で聞く）。依頼書で ☑ の付いたサイズを先頭にして（おすすめ）と付ける：

| 選択肢 | `size` の値 | 仕上がり |
|---|---|---|
| B5横（POP1） | `"B5横"` | 257×182mm |
| A3縦 | `"A3縦"` | 297×420mm |
| 300×864 横 | `"300x864横"` | 864×300mm |
| 300×864 縦 | `"300x864縦"` | 300×864mm |

それ以外は `{"w":mm,"h":mm}` で指定する。塗り足しの既定は 0（これまでの納品と同じ）。印刷所から指定があれば `"bleed": 3` のように入れる。
デザイン案の縦横比と選ばれたサイズが違うときは、**引き伸ばさずに組み直す**（見出しの改行、要素の縦積み・横並びの入れ替え）。サイズ別の組み方は `references/sizes.md`。

## 3. 素材（写真）を準備する
**デザイン案の画像を、文字が入ったまま背景に敷かない**。敷くと、編集できる文字の下に元の文字が透けて残り、打ち替えができなくなる。

1. **商品写真**：依頼書の画像か添付の商品画像を使う。背景が白や四角のままなら切り抜く。使える手段を上から順に試す：
   接続済みの画像ツール（Adobe for creativity の `image_remove_background`、Higgsfield の `remove_background` など）→ `rembg` などのローカルツール → 切り抜かずに角丸の写真枠として置く。
2. **背景・装飾**：まず**ベクトルで作り直す**（グラデーション、放射線、ドット、集中線、帯、リボン）。これがいちばん編集しやすい。
3. **デザイン案にしかない写真**（産地の風景、生産者、ぶどうの房など）：
   - 文字や装飾がかかっていない範囲だけを `crop` で切り出して使う
   - 文字がかかっている場合は、画像編集ツール（Adobe の `image_fill_area`、Higgsfield の画像編集など）で文字を消した版を作る。AI で補った部分があることを、お読みください.txt の `notes` に書く
   - どちらもできなければ、その写真はベクトルの背景で置き換え、本物の写真に差し替えるよう伝える

画像は PNG/JPEG が確実（webp は build 時に自動で PNG に変換される）。解像度は原寸で 150〜350dpi あれば十分。大きすぎる画像は Pillow があれば 350dpi に縮小される。

## 4. layout.json を書く
書き方の全仕様は **`references/spec.md`**（要素の種類、縁取り、長体、縦書き、グラデーション）。見本は `assets/example_b5.json` と `assets/example_long.json`。

- 座標は **mm**、仕上がりの左上が原点。デザイン案のピクセル位置 × (仕上がり幅 mm ÷ 画像幅 px) で換算する
- レイヤーは奥から「背景 → 写真 → 装飾 → 文字」の順に並べる。レイヤー名がそのまま Illustrator のレイヤー名になる
- 書体は `references/fonts.md` の対応表から選ぶ。HGP創英角ﾎﾟｯﾌﾟ体（`pop`）と HGP創英角ｺﾞｼｯｸUB（`kakugo-ub`）が主役。本文と小さい文字は `meiryo-b`
- 見出しや長いコピーには **`maxWidth` を必ず付ける**。実際の HG フォントで幅を超えたとき、jsx が長体で幅内に収める
- 読みやすさの下限：B5 は本文 5mm 以上、A3 は 7mm 以上、300×864 は 10mm 以上（売場で 2〜3m 離れて読む想定）
- 依頼書の運用情報（展開場所・期間・枚数・店着日）は紙面に入れず、`meta` に入れる（お読みください.txt に載る）

## 5. ビルドとプレビュー
```bash
S=<skill>/scripts
python3 $S/build_pop.py build work/layout.json --out work/out/<商品名>_<サイズ>
node    $S/preview.mjs work/out/<商品名>_<サイズ>          # プレビュー.png とチェック結果
```
preview.mjs の報告を読む：
- `長体 NN%` … 75% 未満なら文字サイズを下げるか改行する
- `紙面外にはみ出し` / `端から5mm以内` … 位置を内側へ寄せる（300×864 などホルダーに差す物は特に）

## 6. 見比べて直す（最大 3 周）
プレビュー.png とデザイン案を並べて見て、次の順に直す：
1. 文字の欠け・重なり・読めない配色（まずこれ）
2. 主役（大見出し・煽り文句・商品写真）の大きさと位置
3. 色・縁取りの太さ・装飾の量

直したら 5 をやり直す。3 周で止め、残った差は次の 7 で正直に伝える。

## 7. まとめて渡す
```bash
python3 $S/build_pop.py pack work/out/<商品名>_<サイズ>     # → work/out/<商品名>_<サイズ>.zip
```
ZIP とプレビュー.png をユーザーに渡す（Claude Code なら SendUserFile、claude.ai なら outputs フォルダー）。返信には次を書く：
- 仕上がりサイズ・使用書体
- Illustrator での使い方（ZIP を展開 → ファイル → スクリプト → その他のスクリプト → `AI保存.jsx`）
- デザイン案との主な違い（書体の差、組み直した箇所、写真の出どころ）
- **未確認のこと**：作成環境に Illustrator がないため、Illustrator での読み込みと jsx の実行は未確認であること。プレビューは代替フォントで描いていること

## ZIP の中身
| ファイル | 内容 |
|---|---|
| `<名前>_編集用.svg` | 本体。1 単位 = 1pt で実寸。グループ＝レイヤー、1 行＝1 グループ |
| `AI保存.jsx` | SVG を開き、実寸の補正、レイヤー分け、書体の再設定（入っていない書体は一覧表示）、maxWidth を超えた文字の長体、CMYK 変換、PNG 書き出しを行い、.ai で保存（同名があれば上書きせず `_2` を付ける） |
| `縁取り文字変更.jsx` | 縁取り付きの 1 行を選んで実行すると、重なった文字を一括で打ち替える |
| `プレビュー.png` | 代替フォントで描いた確認用画像 |
| `お読みください.txt` | 使い方、書体、依頼書の運用情報、確認済み／未確認の範囲 |

## よくある失敗
- デザイン案を背景に丸ごと敷く → 元の文字が透ける。手順 3 を守る
- `maxWidth` を付け忘れる → 本物の HG フォントの方が幅が広く、はみ出すことがある
- 縁取りを `stroke` 1 本で済ませる → 文字の内側が削れる。`outlines` を使えば、太い線付きの文字を後ろに重ねる形になる
- 価格・割引率・「日本一」などを勝手に作る → 依頼書にないことは書かない（表示の確認が必要なら shinshohin-hyoji-check スキル）
