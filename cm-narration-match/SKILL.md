# CMナレーション再現

参考CMのナレーションを**測って**、TTS の声をその数値に寄せる。
Claude は音を聴けないので、判断の材料は「元CMとの比較表」と「ユーザーの耳」の 2 つ。毎回両方をそろえて渡す。

```
元CM.mp4 ── analyze_ref.py ─→ profile.json（句の時刻・高さ・声質・スペクトル）＋ script.txt（書き起こし）
                                   │
style.txt ＋ script.txt ── narration_tts.py ─→ tts/tts_<声>.wav（声の候補）── transcribe.py（台本どおりか）
                                   │
              match_ref.py ─→ matched/tts_<声>_matched.wav ── voice_report.py（元CMとの比較表）
              ① 句を元CMの時刻に並べ直す ② 高さを合わせる ③ 濁り・かすれ ④ 元CMの周波数特性に EQ
```

## 0. 準備（初回だけ）
- `pip install numpy praat-parselmouth`、ffmpeg
- Gemini API キー：`export GEMINI_API_KEY=...` かスキル直下の `.env`（`.env.example` をコピー）。キーをファイルに書いてコミットしない
- スクリプトは `scripts/` から直接実行する（`audio_common.py` を同じフォルダから読む）。以下 `S=<このスキル>/scripts`、作業フォルダは `work/`

## 1. 受け取るもの
- **参考CM**（動画でも音声でも可）。必須。無ければ「似せたいCMの動画か音声をください」と頼む。言葉だけの説明で作ると「なんか違う」になりやすい
- 台本（無ければ参考CMの書き起こしをそのまま使う）
- どこを似せたいか（声質・間・音の古さ）。聞けなくても進めてよい

## 2. 参考CMを解析する
```bash
python $S/analyze_ref.py 元CM.mp4 --out work
```
書き起こし・ナレーション区間・句ごとの長さと間・声の高さ・声質が表示される。次の 3 つを確かめる。

1. **台本を元CMと一字一句突き合わせる。** 記憶や思い込みの台本で作ると、どれだけ声を寄せても「違う」と言われる（十万石では「うまい、うまい、うますぎる」と思い込んでいたが、元CMは「うまい、うますぎる」で、最後に「埼玉銘菓、十万石まんじゅう。」があった）。`work/script.txt` を正にして、句ごとに空行で区切る
2. **句の数**が書き起こしとだいたい合っているか。先頭や末尾に音楽が入っていたら `--start/--end`（秒）で範囲を詰めてやり直す。声と音程がかけ離れた区間（尺八など）は自動で外れる
3. **句の中と句の間の音量差**が 30dB 未満なら、声の下に音楽が鳴っている。元CMの HNR・shimmer は実際より濁った値に出るので、その 2 つを追いかけすぎない

## 3. 演出メモ（style.txt）を書く
解析結果から、声の年齢・性別・質感・語り口を自然文で書く。例：`examples/juumangoku/style.txt`
- 質感の言葉が効く：「渋く、しゃがれてざらついた濁りのある地声」「澄んだアナウンサー的な発声ではなく、喉の奥から出る枯れた声」「古いテレビCMのような素朴で淡々とした語り口」
- 間は後処理で元CMに合わせるので、秒数を細かく書かなくてよい。TTS は秒指定をほぼ守らない（指定しても間が 1.5 倍に伸びた）。「句と句の間はたっぷり」くらいで十分
- 「低く」と書くと元CMより低くなりすぎることがある。高さも後処理で合わせるので、高さより質感を書く

## 4. 声の候補を作る
```bash
python $S/narration_tts.py --script work/script.txt --style work/style.txt \
    --voices Algenib Gacrux Enceladus Rasalgethi Alnilam --out work/tts
python $S/transcribe.py work/tts/*.wav --expect work/script.txt
```
- **演出メモを読み上げていないか**を書き起こしで必ず確かめる。メモと台本を分けずに渡すと、TTS はメモまで声に出す（3 行の台本が 40 秒になった）。`narration_tts.py` は見出しで分けて「台本だけ読む」と書いているが、それでも念のため確かめる
- 同じ指示でも毎回少し違う声になる。候補が絞れたら `--takes 3` で同じ声を何回か作って選ぶ

声の候補（Gemini TTS の公式の特徴づけ）。年配・渋い男性ナレーションなら上の 5 つから始める。十万石では **Algenib** が採用になった。

| 声 | 特徴 | 声 | 特徴 |
|---|---|---|---|
| Algenib | Gravelly（しゃがれ） | Charon | Informative |
| Gacrux | Mature（成熟） | Orus | Firm |
| Enceladus | Breathy（息まじり） | Iapetus | Clear |
| Rasalgethi | Informative | Sulafat | Warm |
| Alnilam | Firm | Achernar | Soft |

## 5. 元CMに合わせる
```bash
python $S/match_ref.py --profile work/profile.json work/tts/*.wav --out-dir work/matched
python $S/voice_report.py --profile work/profile.json work/matched/*.wav --markdown
```
- `match_ref.py` は TTS の句を元CMの句に対応づけて（読点で割れた句や、つなげて読まれた句もまとめて対応づける）、元CMと同じ開始時刻に並べ直す。対応は 1 行ずつ表示されるので、句がずれていないか見る
- 比較表で「高さ」「音色差」「間のずれ」が元CMに近いか確かめる。数値上近いものを 1〜2 本推し、全部の候補を送って**聴いて選んでもらう**
- 比較表の項目の意味は `voice_report.py` の冒頭に書いてある。ユーザーには専門用語を言い換えて伝える（HNR→声の澄み具合、スペクトル重心→音の明るさ）

### 参考CMの「音」で別の台本を読ませるとき
「十万石みたいな感じで、こういう台本を読んで」のように、似せたいCMはあるが台本が違う依頼では、元CMの句の時刻は使えない。
声・高さ・音色だけ元CMの `profile.json` から借り、間は台本の句読点で決める。
```bash
python $S/match_ref.py --profile <似せたいCMの>/profile.json work/tts/*.wav \
    --script work/script.txt --gaps "、=0.5,。=1.0" --out-dir work/matched
python $S/voice_report.py --profile <似せたいCMの>/profile.json work/matched/*.wav --no-timing
```
- 間の長さは似せたいCMの測定値から決めるとよい（十万石は「、」約 0.4 秒、「。」約 1.0〜1.25 秒）。ユーザーが「もっと間を」と言えば数値を上げる
- TTS が句読点で区切らずに続けて読んだ所には間を入れられない（対応表に ※ が出る）。その場合はテイクを作り直す
- 人名や地名は TTS が読み違えやすい（清水→きよみず／せいすい）。台本はかなで書いて TTS に渡す
- 例：`audio/shimizu/`（「しみずです。うまい、うますぎる。きよいみずとかいて、しみず。」を十万石の声と音で）

## 6. 聴いてもらって詰める
ユーザーの言葉と、動かすつまみの対応：

| 言われたこと | まず確かめる・動かす |
|---|---|
| なんか違う／全部だめ | 台本が元CMと同じか → 間（比較表の「間のずれ」）→ 声の候補を変える。理由を聞くときは選択肢で聞く（低すぎ／声質・年齢感／読み方／台本） |
| もっと渋く・濁った声 | 演出メモを質感寄りに書き直して候補を作り直す。`--drive`（濁り。既定 3、目安 0〜6） |
| かすれが欲しい | `--husk`（息漏れ。既定 0）。0.3／0.5／0.8／1.2 を `--suffix _husk03` などで作って聴き比べ |
| 高い／低い | `--pitch <Hz>`（省略時は元CMの中央値に合わせる、0 で変えない） |
| こもりすぎ／クリアすぎ | `--eq-hi`（既定 7000Hz。下げると古く狭い音）、`--eq-lo`（既定 90Hz） |
| 間が違う | `profile.json` の `phrases_sec` が元CMの句と合っているか。範囲を `--start/--end` で詰めて解析し直す |

かすれや濁りは数値（HNR）で元CMより濁っていても、聴いた印象では足りないことがある。数値は目安で、最後はユーザーの耳で決める。

## 7. 仕上げ
- 採用版のファイル名と設定（声・テイク・`--drive`/`--husk`/`--pitch`）を記録しておく（例：`examples/juumangoku/README.md`）
- コミットするのは台本・演出メモ・`profile.json`・生成した音声。**参考CMの動画や音声はコミットしない**（他社の著作物。`profile.json` には数値しか入らないので、それだけで作り直せる）
- 報告には比較表と「Claude は聴いていない、最後は耳で確かめてほしい」の一言を添える

## 例：十万石まんじゅう
`examples/juumangoku/` に台本・演出メモ・`profile.json`・採用した設定がある。似た「懐かしいCM風・年配男性」の依頼なら、ここの style.txt から書き始めるとよい。
